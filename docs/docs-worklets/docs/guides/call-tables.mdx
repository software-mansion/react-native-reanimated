# Call tables

Call tables are quick references that show **from which runtimes a given scheduling function can be called**. Since worklets run in [Bundle Mode](/docs/bundleMode), every runtime has access to the full JavaScript bundle and most threading APIs are available on all runtimes - however, some functions can still be called only from specific runtimes.

### How to read a call table

Take [scheduleOnUI](../threading/scheduleOnUI.mdx) as an example:

<CallTable
  calls={{
rnRuntime: true,
uiRuntime: true,
workerRuntime: true,
}}
/>

A green check mark in the table means that the function can be called from that runtime, while a red cross means that calling the function from that runtime will throw an error. So in this case, `scheduleOnUI` can be called from any runtime.

In the following example, the RN Runtime schedules a worker, and that worker schedules a function on the UI Runtime. The UI Runtime receives the task and logs the result.

Compare it with [runOnUIAsync](/docs/threading/runOnUIAsync), which can be called only from the RN Runtime:

<CallTable
  calls={{
rnRuntime: true,
uiRuntime: false,
workerRuntime: false,
}}
/>
