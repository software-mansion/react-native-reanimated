# Running worklet functions on the UI runtime

The Worklets library provides three functions for running a [worklet function](../tutorials/0-concurrency-model.mdx#worklet-functions) on the [UI Runtime](../concepts/runtimeKinds.mdx#ui-runtime) from the [RN Runtime](../concepts/runtimeKinds.mdx#rn-runtime): [`scheduleOnUI`](../threading/scheduleOnUI.mdx), [`runOnUIAsync`](../threading/runOnUIAsync.mdx) and [`runOnUISync`](../threading/runOnUISync.mdx).
They differ in whether the worklet function runs asynchronously or synchronously, and in what they return to the caller.
Use the table below to pick the one that fits your case.

## Comparison

|  | [`scheduleOnUI`](../threading/scheduleOnUI.mdx) | [`runOnUIAsync`](../threading/runOnUIAsync.mdx) | [`runOnUISync`](../threading/runOnUISync.mdx) |
| --- | --- | --- | --- |
| **Execution** | Asynchronous | Asynchronous | Synchronous, blocks the caller until the worklet function returns |
| **Returns** | Nothing | A `Promise` that resolves with the worklet function's return value | The worklet function's return value directly |
| **Web support** | ✅ | ✅ | ❌ |
| **Use when** | You want to run a worklet function on the UI Runtime and don't need its result back | You need the worklet function's result back, but don't want to block the calling thread | You need the worklet function's result immediately, within the same synchronous flow |

The values returned by `runOnUIAsync` and `runOnUISync` have to be [serializable](../memory/serializable.mdx).

All three functions can be called from the [RN Runtime](../concepts/runtimeKinds.mdx#rn-runtime), and additionally from the [UI](../concepts/runtimeKinds.mdx#ui-runtime) and [Worker](../concepts/runtimeKinds.mdx#worker-runtime) Runtimes when [Bundle Mode](../bundleMode/overview.mdx) is enabled.
See [Call tables](./call-tables.mdx) for the full matrix.
