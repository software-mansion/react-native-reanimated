<Badges version="0.14.0">
  # setSerializableCounterpart
</Badges>

When Worklets [serializes](/docs/memory/serializable) an object, for example when a [worklet](/docs/fundamentals/glossary#worklet) captures it in its closure, it sends a serialized counterpart of that object to the other Runtime. Worklets remembers the counterpart for each object. `setSerializableCounterpart` lets you set it manually.

## Reference

```typescript
import { scheduleOnUI, setSerializableCounterpart } from 'react-native-worklets';

const flag = { current: false };
setSerializableCounterpart(flag, { current: true });

scheduleOnUI(() => {
  console.log(flag.current); // logs `true`
});
```

<details>
  <summary>Type definitions</summary>

  ```typescript
  function setSerializableCounterpart(value: object, counterpart: unknown): void;
  ```
</details>

## Arguments

### value

The object to set the counterpart for. It's compared by reference.

### counterpart

The value to send in place of `value`. It's serialized once, when `setSerializableCounterpart` is called. It can also be a [SerializableRef](/docs/memory/isSerializableRef), which is used as is.

## Remarks

- The new counterpart overwrites the existing one for `value`, including one that Worklets created when it serialized `value` earlier.
- Use [hasSerializableCounterpart](/docs/memory/hasSerializableCounterpart) to check whether `value` already has a counterpart.
- Use [removeSerializableCounterpart](/docs/memory/removeSerializableCounterpart) to remove the counterpart.
- On the Web `setSerializableCounterpart` does nothing, because values aren't serialized there.
