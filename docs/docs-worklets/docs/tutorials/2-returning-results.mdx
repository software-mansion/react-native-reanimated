# Returning results

In the [previous chapter](/docs/tutorials/your-first-worklet) we dispatched some console logs to
other Runtimes. However, logging itself is not particularly useful.

In this chapter we'll learn how to obtain execution results from dispatched worklet functions.

## Synchronously

Simplest way of returning values. [`runOnUISync`](/docs/threading/runOnUISync) and
[`runOnRuntimeSync`](/docs/threading/runOnRuntimeSync) functions return the result of a worklet
function directly to the invoking Runtime:

<ThreadingSimulation module={ReturningSyncSnippet} source={ReturningSyncSource}/>

:::note Synchronous calls stay on the calling thread

A runtime holds JavaScript code and data; a thread executes code in it. Here, `runOnUISync` and
`runOnRuntimeSync` let the JS thread temporarily acquire the target runtime and run `foo` there,
waiting if that runtime is busy. This gives synchronous access to that runtime's data while keeping
the JS thread occupied, which is why the simulation shows it connected to different runtimes.

:::

However, dispatching this calculation synchronously doesn't free the calling thread. We could
also call `foo` directly on the RN Runtime:

<ThreadingSimulation module={ReturningDirectSnippet} source={ReturningDirectSource}/>

Both the function and its caller execute on the JS thread and the result is immediately available.
To let the calling thread do other work while a calculation runs on another thread, we need an
asynchronous call. We'll explore when synchronous calls are useful in future sections.

## Asynchronously

For asynchronous returns, i.e. results of complex calculations, you can use
[`runOnUIAsync`](/docs/threading/runOnUIAsync) and
[`runOnRuntimeAsync`](/docs/threading/runOnRuntimeAsync) functions. They return an awaitable
promise.

Remember that [`scheduleOnUI`](/docs/threading/scheduleOnUI) and
[`scheduleOnRuntime`](/docs/threading/scheduleOnRuntime) functions do not return a value.

<ThreadingSimulation module={ReturningAsyncSnippet} source={ReturningAsyncSource}/>

The scheduling runtime is free to keep executing JavaScript code until you await the returned
promise. In this example we dispatched the invocations on `complexTask` before awaiting - to execute
them concurrently. While the RN Runtime awaits, its thread is free to run other tasks.
