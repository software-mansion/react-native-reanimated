# Setup

Bundle Mode is the only mode of running worklets, so every native app using `react-native-worklets` has to be configured as follows:

## Configure Worklets plugin

1. **Add the Worklets plugin to your Babel configuration**. The [Worklets plugin](../worklets-plugin/about.mdx) extracts each worklet function into a module that Worklet Runtimes load from your bundle.

<Tabs groupId="worklets-plugin" queryString>
  <TabItem value="babel" label="Babel plugin">
    ```javascript {7}
    module.exports = {
      presets: [
        ... // don't add it here :)
      ],
      plugins: [
        ...
        'react-native-worklets/plugin',
      ],
    };
    ```

    The plugin needs no options. See [Options](../worklets-plugin/options.mdx) for what you can configure.
  </TabItem>

  <TabItem value="oxc" label="Oxc plugin">
    ```javascript {7}
    module.exports = {
      presets: [
        ... // don't add it here :)
      ],
      plugins: [
        ...
        'react-native-worklets/plugin-oxc/babel',
      ],
    };
    ```

    The Oxc plugin needs no options either. See the [Oxc plugin](../worklets-plugin/oxc.mdx) page.
  </TabItem>
</Tabs>

## Configure Metro

2. **Modify your Metro configuration**. Metro needs to be configured to pre-load Bundle Mode entry points into your JavaScript bundle and to resolve the worklet modules the plugin emits. In your `metro.config.js` file, apply the config required for Bundle Mode. For example:

<Tabs groupId="framework">
  <TabItem value="expo" label="Expo">
    ```javascript {3,10}
    // Learn more https://docs.expo.io/guides/customizing-metro
    const { getDefaultConfig } = require("expo/metro-config");
    const { getBundleModeMetroConfig } = require("react-native-worklets/bundleMode");

    /** @type {import('expo/metro-config').MetroConfig} */
    let config = getDefaultConfig(__dirname);

    // Your modifications to the config

    config = getBundleModeMetroConfig(config);

    module.exports = config;
    ```
  </TabItem>

  <TabItem value="react-native-community" label="React Native Community">
    ```javascript {6,12-16}
    const {
      getDefaultConfig,
      mergeConfig,
    } = require('@react-native/metro-config');

    const { bundleModeMetroConfig } = require('react-native-worklets/bundleMode');

    const config = {
      // Your Metro config
    };

    module.exports = mergeConfig(
      getDefaultConfig(__dirname),
      bundleModeMetroConfig,
      config
    );
    ```
  </TabItem>
</Tabs>

`bundleModeMetroConfig` sets `serializer.polyfillModuleNames`. `mergeConfig` replaces this array, it does not concatenate it. If your Metro config sets `serializer.polyfillModuleNames` too, use `getBundleModeMetroConfig`, which appends to your list:

```javascript
const {
  getDefaultConfig,
  mergeConfig,
} = require('@react-native/metro-config');

const { getBundleModeMetroConfig } = require('react-native-worklets/bundleMode');

const config = {
  // Your Metro config
};

module.exports = getBundleModeMetroConfig(
  mergeConfig(getDefaultConfig(__dirname), config)
);
```

## Let Metro see the worklet modules

The plugin emits each worklet module in one of two ways, depending on the Metro version it runs under. Metro tells the plugin which one it supports through the `supportsInlineModules` Babel caller flag.

### Metro with inline modules

A Metro that supports `metro:inline` specifiers and virtual modules ([react/metro#2037](https://github.com/react/metro/pull/2037)) receives each worklet module inline, as a `require("metro:inline;base64,<module>")` dependency of the file that defines the worklet, and resolves it to a virtual module beside that file. Nothing is written to disk and Metro caches each worklet module like any other file. `bundleModeMetroConfig` and `getBundleModeMetroConfig` enable `resolver.unstable_allowVirtualModules` for you when they detect such a Metro.

No released Metro includes this support yet. Until one does, apply the `metro`, `metro-config`, `metro-babel-transformer`, `metro-transform-worker` and `@react-native/metro-babel-transformer` patches for Metro 0.87.2 and React Native 0.88 from the [Worklets repository](https://github.com/software-mansion/react-native-reanimated/tree/main/packages/react-native-worklets/bundleMode/patches).

### Other Metro versions

With any other Metro, the plugin writes each worklet module into `react-native-worklets/.worklets/<hash>.js` while it transforms your code. Metro does not index files created mid-build in time, so without a patch you will see "Failed to get the SHA-1 for ..." errors:

<ThemedImage
  sources={{
light: useBaseUrl('/img/sha-light.png'),
dark: useBaseUrl('/img/sha-dark.png'),
}}
  alt="Bundle Mode Metro error logs"
/>

Apply the `metro` patch for your Metro version from the [Worklets repository](https://github.com/software-mansion/react-native-reanimated/tree/main/packages/react-native-worklets/bundleMode/patches). **This patch does not require building React Native from source**.

## Enable fast refresh on Worklet Runtimes

_This step is optional but highly recommended._

React Native's Fast Refresh (hot reload) feature doesn't apply to Worklet Runtimes out of the box. Therefore, when you change a worklet function's code you will see an error "\[Worklets] Unable to resolve worklet from module ...".

<ThemedImage
  sources={{
light: useBaseUrl('/img/hot-light.png'),
dark: useBaseUrl('/img/hot-dark.png'),
}}
  alt="Bundle Mode Fast Refresh error logs"
/>

This is due to the fact that the Fast Refresh update wasn't sent to the Worklet Runtime and it doesn't know that the module holding the new worklet function exists.

To fix this issue you can do one of the following:

1. Reload the app on each worklet code change. This virtually defeats the purpose of Fast Refresh. Not recommended.
1. Patch `metro-runtime` package for it to send Fast Refresh updates to Worklet Runtimes. This is the recommended approach. **This patch does not require building React Native from source**. You can find patching instructions in the [Worklets repository](https://github.com/software-mansion/react-native-reanimated/tree/main/packages/react-native-worklets/bundleMode/patches).

This patch is a temporary workaround until necessary changes are merged into Metro.

## Final steps

Make sure to clear your Metro bundler's cache to ensure that all the changes are applied correctly.

<Tabs groupId="package-managers">
  <TabItem value="npm" label="NPM">
    ```bash
    npm start -- --reset-cache
    ```
  </TabItem>

  <TabItem value="yarn" label="YARN">
    ```bash
    yarn start --reset-cache
    ```
  </TabItem>
</Tabs>

And that's it! You can now happily enjoy worklets! You can learn more about using Bundle Mode [here](./usage.mdx).
