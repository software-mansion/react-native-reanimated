# Fading content

<Badges version="4.8.0">`fadeContent()` changes the children of a shared view in steps.</Badges>

By default, the view moves together with its own children, and the children of the target view show at once when the transition ends. When the two views have different children, for example a card in a list and a header on a details screen, this change is sudden. With `fadeContent()`, the children of the moving view fade out while it moves, and the children of the target view fade in when the transition ends. The view itself stays visible, and its frame and style animate as usual.

## Reference

```tsx
import Animated, { SharedTransition } from 'react-native-reanimated';

// highlight-next-line
const transition = SharedTransition.duration(450).fadeContent();

function Card() {
  return (
    <Animated.View
      sharedTransitionTag="card"
      sharedTransitionStyle={transition}>
      <Text>Florence</Text>
    </Animated.View>
  );
}
```

### Arguments

#### `config` <Optional/>

An object with two optional fields:

- `fadeOut.end` - the point of the move, more than 0 and at most 1, where the children reach opacity 0. For example, with `0.5` the children are gone in the middle of the move. The point follows the easing or the spring of the move. Defaults to `1`.
- `fadeIn.duration` - the length of the fade-in after the transition ends, in milliseconds. Defaults to half of the transition duration.

```tsx
const transition = SharedTransition.duration(450).fadeContent({
  // highlight-next-line
  fadeOut: { end: 0.5 },
  // highlight-next-line
  fadeIn: { duration: 150 },
});
```

## Remarks

- Only the direct children of the shared views fade. A child that fills the view, for example a background image, fades like the other children.
- A shared view without children, for example a shared `Image`, has nothing to fade.
- A direct child with its own matching `sharedTransitionTag` moves on its own and does not fade with its parent. Use this for children that are on both screens, for example an icon.
- A direct child of the target view with an [`entering`](../layout-animations/entering-exiting-animations.mdx) animation plays it after the transition ends, in place of the fade-in. Deeper children play their entering animations during the move.
- The transition uses the builder of the view that it starts from. To fade the content in both directions, give `fadeContent()` to both views.
- If the user goes back during the move, the children fade in again while the view returns.
- With [`SharedTransition.custom()`](./custom-animations.mdx), only the fade-in works. The children of the moving view do not fade out.
- With `.springify()`, the fade-in starts when the spring stops. Pass the duration to `springify(duration)`, because the default fade-in length comes from it.
