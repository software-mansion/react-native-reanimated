  # Shared Element Transitions
</Badges>

Shared Element Transitions move a view from one screen to another. When you navigate, a view on the old screen moves to the position of the matching view on the new screen. Its size and style change during the transition.

## Your first shared element transition

```tsx
import { Pressable } from 'react-native';
import { useIsFocused } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import Animated, { SharedTransitionBoundary } from 'react-native-reanimated';

const Stack = createNativeStackNavigator();

function ListScreen({ navigation }) {
  return (
    <Pressable onPress={() => navigation.navigate('Details')}>
      <Animated.View
        // highlight-next-line
        sharedTransitionTag="photo"
        style={{ width: 100, height: 100, backgroundColor: '#b58df1' }}
      />
    </Pressable>
  );
}

function DetailsScreen() {
  return (
    <Animated.View
      // highlight-next-line
      sharedTransitionTag="photo"
      style={{ width: '100%', height: 300, backgroundColor: '#b58df1' }}
    />
  );
}

function ScreenBoundary({ children }: { children: React.ReactNode }) {
  const isFocused = useIsFocused();

  return (
    // highlight-next-line
    <SharedTransitionBoundary isActive={isFocused}>
      {children}
      // highlight-next-line
    </SharedTransitionBoundary>
  );
}

function App() {
  return (
    <Stack.Navigator
      // highlight-next-line
      screenLayout={({ children }) => <ScreenBoundary>{children}</ScreenBoundary>}>
      <Stack.Screen name="List" component={ListScreen} />
      <Stack.Screen name="Details" component={DetailsScreen} />
    </Stack.Navigator>
  );
}
```

To make a shared element transition:

1. Give the same [`sharedTransitionTag`](./shared-transition-props.mdx#sharedtransitiontag) to an animated component on each screen.
1. Wrap each screen in a [`SharedTransitionBoundary`](./screens-and-boundaries.mdx#sharedtransitionboundary). Set `isActive` to `true` on the screen that the user sees. In the example, the [`screenLayout`](https://reactnavigation.org/docs/navigator/#screen-layout) prop of the navigator wraps all of its screens. For other ways to wrap screens, see [Usage with navigation](./screens-and-boundaries.mdx#usage-with-navigation).

When the active boundary changes, Reanimated finds the views with the same tag in the old and the new boundary and runs the transition between them.

## How it works

During the transition, Reanimated moves the view from the old screen above the screen content and hides the view on the new screen. Then it animates the moving view from its old frame and style to the frame and style of the new view. When the animation ends, the view on the new screen shows in its place.

By default, the transition is a 500 ms [`withTiming`](../animations/withTiming.mdx) animation of every property that is different on the two views:

- position and size,
- `opacity` and `backgroundColor`,
- `borderRadius`, `borderWidth` and `borderColor`, also per side and per corner,
- `transform` and `transformOrigin`,
- `boxShadow` and the `shadow*` properties,
- on Android, `elevation`.

The view moves together with its own children, and the children of the target view show at once when the transition ends. When the two views have different children, for example a card in a list and a header on a details screen, this change is sudden. To fade the old children out and the new children in, use [`fadeContent()`](./children-of-shared-views.mdx#fadecontent).
